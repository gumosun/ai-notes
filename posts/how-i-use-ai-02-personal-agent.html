02我如何使用 AI

Personal agent：
我把「全局」交給了一個空資料夾

我的每個專案各自都跑得不錯，問題是「全局」只存在我的腦袋裡——而我的腦袋是一個會忘記事情、還會自我欺騙的儀表板。這篇講我怎麼把全局交給一個 AI agent：從一個空資料夾和一份職位說明書開始，到它變成一顆跟我共用記憶的附屬大腦。

我如何使用 AI・第 2 篇｜閱讀約 9 分鐘

一我根本不知道自己的注意力長這樣

我的桌面上有十幾個資料夾。一個開發中的求職產品、一個每天在用的台股掃描器、理財儀表板、求職資料，還有幾個已經沒在動的顧問案。

自我欺騙不是形容詞，是有數據的。我一直「覺得」自己在平均推進兩個重點專案。直到有一天把四週的 git 紀錄（程式碼的變更歷史，每次存檔都有時間戳）拉出來算：九成的投入集中在同一個專案上，另一個號稱並列主力的，只拿到零頭。

不是那個專案不值得做。是我根本不知道自己的注意力長這樣。

二動手前，我想過的三條路

第一條：更認真地用工具。看板、週報模板、Notion 儀表板——我都認識，有的還試過。它們的共同死因：更新和回顧都靠我自己記得做。一個需要我維護的「全局」，忙起來第一個被犧牲的就是它，而忙起來恰恰是最需要全局的時候。

第二條：每次問 AI。我本來就常把狀態貼給 AI 請它幫我分析。單次效果不錯，致命傷是它不記得我——每次都要重新解釋背景，分析品質取決於我當下餵了什麼，而「我會漏餵什麼」正是問題本身。

第三條（我選的）：給 AI 一個資料夾和一份職位說明書，讓它長期上班。我開了一個空資料夾，只放一份 markdown 文件，跟 Claude Code 說：這裡歸你管，你是我的 personal agent。一開始我叫它「幕僚長」，因為最初的任務就是替我看專案全局——後來發現這個名字太小看它了，這個到文末再講。關鍵差異在於記憶的歸屬——資料夾裡的檔案就是它的長期記憶，它自己寫、自己維護，我不用記得更新任何東西。附帶的好處：全部在本機、有 git 版本紀錄，我的財務和求職資料不用上任何雲端服務。

三職位說明書裡寫了什麼

事後整理，那份文件其實就五件事，這也是整個系統的骨架：

  1. 追蹤名單：它管哪幾個專案、各自的資料夾在哪
  2. 開場例行：每次我打開對話，不等我開口，先去各專案的 git 紀錄 diff 出「上次之後發生了什麼」、更新狀態卡、給我 30 秒簡報
  3. 收尾例行：每次結束前寫工作日誌，並且把「這次對我這個人的新理解」合併進一份人物模型文件
  4. 紅線：什麼不准做——例如任何東西要對外發佈，永遠是我手動按的
  5. 講話授權：當我說要做 A 卻一直在做 C，它必須主動講，不用客氣

第 3 點值得展開，因為它是這個系統跟「待辦清單工具」的本質差別。它的記憶是兩層的：下層是原始日誌（每次談了什麼，只增不改），上層是人物模型——它對我的目標、做事風格、決策習慣的持續理解，每次對話後更新、過時的理解會被改掉。建議是從這個模型長出來的，所以它越用越準。

圖 1｜三路輸入，一份人物模型。左邊是它看我的三個管道，右邊是它給我的兩種輸出——中間那份文件才是系統的核心：建議是從理解長出來的。

抓落差靠的是第 5 點加上兩層資料：一層記「宣告」（我拍板過的優先序，白紙黑字含日期），一層記「行為」（git 活動＋對話紀錄）。兩層都有，落差才是算得出來的——不然所謂自我覺察，只是感覺良好。

它上線第一天就抓到開頭那個九成對零頭。被點出來之後那一週，比例回到約 63:37——沒有人逼我，「被看見」本身就有矯正力。但故事沒有到此圓滿：後來產品上線衝刺，比例又歪了回去，它把這件事掛成「待討論」繼續追。落差不一定是我的行為飄了，也可能是我的目標其實已經悄悄換了、只是文件沒跟上——這種時候該修的是宣告文件，不是我。兩種都算好結果，重點是把「漂移」變成一個可以攤開來談的東西。

四真的用了之後，露餡的三個地方

第一，我把它的目標設錯了。第一版職位說明書寫的是「幫我達成我的目標」。聽起來合理，跑了幾天發現不對勁：我的目標會變，而且應該被允許變。如果它的使命綁在某個具體目標上，我哪天想法變了，它整個存在的前提就塌了。

第二，它只在我開機時活著。所有的掃描、提醒、簡報，都發生在「我打開對話」之後。我不開，它就不存在——說好的每週讀產業情報，三週過去累積筆記數是零，因為那件事依賴的還是我的自律，而外包紀律不正是當初的目的嗎。

第三，整理的結果散得到處都是。狀態在檔案裡、摘要在對話裡、關鍵數字是某天手抄的快照。手抄快照的問題是會過期——像現金水位這種每天在變的數字，抄下來的第二天就是舊的，而我後來需要拿它做重要決定。

五針對這三個洞做的調整

使命重設。它的目標函數從「幫我達成目標」改成一句：持續理解我。我在做什麼、怎麼做事、想要什麼——理解夠準，建議自然有用。目標是我的，會換；「理解我」不會換。順序反過來之後，系統才站穩。

給它接上手腳。行事曆、信箱、記帳試算表直連——關鍵數字它每次自己去讀最新的，不再手抄。然後給它一個每週自動執行的雲端分身：不管我開不開機，每週一早上自動掃完固定情報源、把摘要寄進我的信箱。它從「等我開機的顧問」變成「自己會動的幕僚」，我的自律從迴路裡被拿掉了。

立一條 source of truth 規矩。email、對話、通知都只是傳遞通道，所有整理最終必須落地在同一個 dashboard 頁面。要回顧全局，永遠只看一個地方。

六從幕僚長到附屬大腦

補完這三個洞之後，我發現它做的事早就超出「幕僚長」的職位說明書了。現在的它：行事曆和信箱是它的感官——開場簡報會提醒我這週有什麼行程、有哪封信該處理，每週的情報摘要它自己掃、自己寄；記帳試算表是它的儀表——現金水位這類關鍵數字它直接讀最新的，我做重要決定時它拿得出即時的帳；知識庫是我們的共筆——我最近開了一個 Obsidian 庫（本地的 markdown 筆記軟體，靠雙向連結把筆記織成網），分工是「我丟、它整理」：我把有感的東西隨手扔進收件匣，它每次上班把值得留的寫成正式筆記、掛上連結、長出知識網。我讀到的、聊到的、學到的，開始真正累積在一個地方，而維護成本不在我身上。

圖 2｜附屬大腦全景。工具是一堆各自獨立的功能；附屬大腦的差別在記憶是同一份——左邊全部的輸入、右邊全部的輸出，中間共用同一個「它對我的理解」。

所以我現在對它的定位是：personal agent——一顆跟我共用記憶的附屬大腦。它不是一堆工具的集合，差別在記憶是同一份：專案的狀態、我的行程、我的財務、我的知識、還有「它對我這個人的理解」，全部長在一起。工具是你去用它；附屬大腦是它認識你，然後跟你協作。

還開著的缺口也照實說：我快要回去上班了。目前整套系統是為「全職做自己專案的我」設計的，等我的時間被工作吃掉大半，它的節奏、優先序、甚至存在方式都要重新設計——這會是這個系列之後的題目。

七如果你想試：起手清單

不用寫程式，你需要的是一個資料夾＋一份職位說明書，裡面寫清楚五件事：

  1. 追蹤名單——它替你看著哪些東西
  2. 開場例行——每次見面它先自己做什麼（重點：不等你開口）
  3. 收尾例行——結束時它怎麼記住這次，尤其是「對你的新理解」記在哪
  4. 紅線——什麼事永遠必須由你手動做
  5. 講話授權——明確寫下「發現我言行不一時，你必須說」

一個經驗法則：先讓這個迴路手動跑順一兩週，再考慮接自動化。我的自動化全是被真實的洞逼出來的——反過來先蓋自動化，多半在蓋一座沒人住的城。
