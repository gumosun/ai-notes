02AI 學徒筆記

AI 為什麼一本正經地胡說？
以及它為什麼這麼燒錢

上一篇說到，LLM（Large Language Model，大型語言模型——ChatGPT、Claude 這類 AI 的正式名稱）的本質是接龍：看著全桌的 token，出一張機率表，抽一塊，接上去。這一篇把接龍推到底，回答兩個最常被問的問題——幻覺是怎麼來的？錢是燒在哪裡的？第二題的答案，會一路通到 AI 供應鏈。

學徒筆記系列・第 2 篇｜閱讀約 9 分鐘

一它算的是「像不像」，不是「對不對」

先把接龍的結論推到底：模型被訓練的唯一目標，是讓吐出來的下一塊積木「最像」訓練語料裡會出現的樣子。它體內沒有一個資料庫可以查證、也沒有一個「事實」開關。流暢、通順、有自信，是它的本職；剛好說對，是這個機制常見的副作用——因為訓練語料裡大部分的話恰好是對的。幻覺不是它「故障」，是同一套機制在條件不利時的自然輸出。

四個幻覺來源

來源發生了什麼
① 知識是有損壓縮幾兆 token 的語料被壓進幾千億個參數裡——像把整座圖書館燒成一塊「統計印象」。常見的知識（台灣最高峰）印象深刻；冷門的知識（某小公司 2019 年的營收）印象模糊。模糊的地方它不會空白，會用「最像的樣子」補起來——編一個格式完美的假數字。
② 沒有天然的「我不知道」出口接龍機制天生「必須接下去」。訓練後期人類會教它說「我不確定」，但這是後天補丁——而且調校時「有幫助的完整回答」常常得分更高，等於偷偷獎勵了敢講。
③ 一步錯、步步錯抽出來的每一塊都成為下一輪的「事實前提」。開頭如果抽錯了一塊（說了「該論文由王教授發表」），後面的接龍會忠實地圓這個謊——補出論文標題、年份、期刊，全都像模像樣。它不是在騙你，它是在對著錯的桌面認真接龍。
④ 語料本身有錯、有過期訓練資料是某個時間點以前的網路文字——裡面本來就有錯誤、謠言、舊資訊。壓縮得再好，源頭錯了輸出就錯。

為什麼你會被騙：流暢 ≠ 正確

人類的直覺裡，「講得又快又順又有細節」的人通常真的懂。這條經驗法則在 LLM 上完全失效：它的流暢度來自機制本身，跟內容真假無關。它說對的時候是這個語氣，胡編的時候還是這個語氣——你無法從語氣分辨，它自己也分辨不了（它沒有「我在編」的自覺，每一輪都只是誠實地輸出機率表）。

怎麼緩解（以及為什麼根治不了）

所有緩解手段的共同思路只有一個：把「憑印象回憶」改成「打開資料查閱」。

手段原理
RAG／檢索增強
（Retrieval-Augmented Generation：先檢索資料、再生成回答）		回答前先搜尋，把找到的原文攤在桌面上——模型「照著唸」遠比「憑印象背」可靠
工具使用算數交給計算機、查價交給外部程式服務——不讓接龍機制做它不擅長的事

但只要底層機制還是「機率接龍」，幻覺就只能壓低、不能歸零——它是這個架構的本性，不是 bug 清單上等著被修掉的一項。理解這點，你就能判斷什麼任務能放心交給 LLM（有資料可查、錯了容易發現），什麼任務要人盯（冷門事實、高代價決策）。

前半一句話

幻覺＝壓縮印象的模糊處＋必須接下去的機制＋一步錯步步錯的圓謊。緩解的唯一思路是「把回憶變查閱」，而根治不存在。

二錢燒在哪：每個 token 都是一次全力衝刺

回到接龍迴圈：每吐一塊積木，模型都要「重新算一輪」。這一輪的份量有多大？粗略但夠用的直覺：生成一個 token，約等於把模型的所有參數都拿出來各做一次乘法加法。一個幾千億參數的模型，就是每個 token 幾千億次計算——你看它輕鬆聊天，背後是每個字都在全力衝刺。

真正的瓶頸不是算，是「搬」

更關鍵的是一個反直覺的事實：作答（decode）階段，晶片——通常是 GPU（Graphics Processing Unit，圖形處理器：原本為遊戲畫面設計，因為擅長同時做海量簡單計算，成了 AI 運算的主力晶片）——大部分時間不是在計算，而是在搬資料。模型的參數（幾百 GB）放在晶片旁邊的記憶體裡，每生成一個 token，都得把參數整套搬進運算單元過一遍。運算單元快得要命，等資料搬進來的時間反而是大頭——像一個世界冠軍廚師，做菜三秒鐘，等食材送到要三十秒。

HBM（High Bandwidth Memory，高頻寬記憶體）＝把記憶體晶片像疊疊樂一樣堆高、緊貼在處理器旁邊，一切都為了把「搬運速度」拉到極限。這就是它成為 AI 硬體核心零組件的原因——下一篇會從這裡接到供應鏈。

另外，上一篇說的「桌面」也要花記憶體：對話越長，桌面上要隨手可查的中間結果（術語叫 KV cache，Key-Value 快取——「算過的先存著」的暫存區）就越大。長上下文不只慢，還直接吃掉昂貴的記憶體容量——這是為什麼「支援百萬 token 上下文」是一句很貴的話。

需求為什麼爆炸：不是用的人變多而已

如果 token 用量只隨使用人數線性成長，故事就平淡了。真正陡的是每個任務吃的 token 在放大：

推理模型＝作答前先吐一長串「思考 token」自我推演。Agent＝像 Claude Code 這類工具：一個任務背後是幾十上百次模型呼叫，每次都帶著完整脈絡。AI 應用正從左往右移動——需求曲線因此比使用人數陡得多。
把兩篇串起來

模型用接龍生成 → 每塊積木都要整套搬運參數 → 應用形態從聊天走向推理模型與 agent，單任務 token 量放大百倍千倍 → 所以「token 需求」不是抽象名詞，它一路換算成：算力 → 高頻寬記憶體 → 先進封裝 → 晶圓 → 電力與散熱。

下一篇預告：把這條需求往上游一層層推——誰做晶片、誰把記憶體疊到晶片旁邊、誰封裝、誰代工、誰供電散熱，以及台灣的公司各自站在哪個環節。從 LLM 原理直通 AI 供應鏈的投資視角。
